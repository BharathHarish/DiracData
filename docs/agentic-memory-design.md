# DiracData — Agentic Memory (schema-scoped, async, self-curating)

**Status:** design + build in progress · **Builds on:** the durable conversation memory (transcript.md /
summary.md). Same architecture, moved to schema scope, made async, given CRUD tools.

## 1. The shape (same as transcript.md / summary.md)

Two layers, both durable in the object store — identical skeleton to conversation memory:

| | Conversation memory (built) | Agentic memory (this doc) |
|---|---|---|
| Lossless append layer | `conversations/<id>/transcript.md` | `experiences/<schema>/candidates/` (turn traces enqueued) |
| Compact agentic layer | `conversations/<id>/summary.md` (regenerated by the **summarizer**) | `experiences/<schema>/experiences.md` (curated by the **curator**) |
| Scope | per conversation | per **schema** (cross-conversation, cross-session) |
| Update timing | in-band, after the answer | **async — a background thread after the turn** (never blocks a follow-up) |
| Compact operation | rewrite one doc | the curator has **tools** (`read_experiences`, `update_experiences`) and edits sections |
| Fed to the next turn | whole summary at framing | retrieved by section/subject, injected at the right stage |
| Agentic fold | `make_summarizer(prev, turn) -> new_summary` | `make_curator(book, candidate) -> updated book` |

The curator is the summarizer's bigger sibling: `(existing compact memory + new turn) -> updated compact
memory`, by **LLM judgement**, prompt in `prompts/curate.md`.

## 2. experiences.md — a typed, curated knowledge doc

Human-readable markdown with a section per KIND (the taxonomy is agentic/extensible; these seed it):

```
## SQL PATTERNS        # reusable template + bindings (e.g. new-vs-returning cohort CTE)
## RCA LEADS           # "when metric M drops, check dimension D first (drove the Q3 dip)"
## GOTCHAS             # non-obvious data caveats (billing_client_ref has 14 nulls -> unclassified)
## BINDINGS            # term -> SQL/logic learned/refined (online_revenue = SUM(net_paid))
## VALUE DOMAINS       # real values/casing (state = 2-letter UPPER; gender in {'F','M'})
## PREFERENCES         # resolved user intent ("customers from TX" = current billing address state)
```

Each entry is one succinct bullet. The curator keeps the doc **relevant and short** by judgement —
plain **append / update / delete**, merging near-dups and pruning stale. No tiers, no stats, no scoring.

## 3. The async pipeline (background thread + durable queue)

```
turn answer delivered
   ├─(instant, synchronous)─▶ append CANDIDATE (the turn trace) to experiences/<schema>/candidates/   [durable, no loss]
   └─▶ answer returns to the user (follow-up proceeds immediately)

background daemon thread (per turn):  drain candidates ─▶ Curator agent ─▶ read_experiences + update_experiences ─▶ experiences.md
```

- **Non-blocking:** enqueue is a cheap append; the follow-up never waits on curation.
- **No loss on single-shot exit:** candidates are durable; a leftover is drained next session or by
  `scripts/consolidate.py`. (In a REPL the thread runs between turns; in `--question` mode it may be
  drained next run.)
- **Batchable:** the curator can process several candidates in one pass (cheaper, better cross-turn dedup).

## 4. What the curator sees + decides (full breadth)

Input = the whole turn (we already persist it): the framed intent + bindings, the SQL(s), results, the
RCA dimensions explored + the finding, DQ flags, clarifications, the final answer. From that it mines
salient, durable knowledge of ANY kind and, per fact, decides: **add · update · merge · skip · delete**.
Most turns yield nothing new — "learn only if useful" is the curator's judgement, not a rule.

**Good entry (per-kind, same spirit):** reusable · non-obvious · generalizable (template/heuristic, not
a one-off) · grounded in real tables/columns/terms · distinct (else merge). A bare `COUNT(*)` or a
one-off with no transferable lesson is discarded.

**Succinct by judgement:** the curator keeps the doc short with plain **append / update / delete** --
no promotion/decay machinery, no caps to tune.

## 5. Retrieval (kind-aware injection)

Not dumped wholesale. Each kind surfaces where it helps: SQL patterns + bindings at framing/authoring
(via `find_examples`/`define`); an `rca_lead` when framing an RCA on that metric; a `gotcha`/`value_domain`
when its column enters scope.

## 6. Milestones (each flagged off, suite green at each)

- **M0** — `ExperienceBook` (read/write `experiences.md` in the object store, section-aware) + config
  flag `agentic_memory_enabled`. No behaviour change.
- **M1** — durable candidate queue on the `_record` hook + background daemon thread that drains it.
  Non-blocking; single-shot safe.
- **M2** — the **Curator agent** (`agents/curator.py`, `make_curator`) with `read_experiences` /
  `update_experiences` tools + `prompts/curate.md`. Agentic add/update/merge/skip/delete.
- **M3 (simplified)** — no decay/promotion machinery (dropped as over-engineering). The curator's
  append/update/delete + succinct-by-judgement is enough. Just exercise the remaining sections
  (RCA LEADS / VALUE DOMAINS / PREFERENCES) live.
- **M4 (the payoff)** — `find_examples` / framing READ the curated book so entries are retrieved and
  reused on the next query; absorb the legacy append-only `ExperienceStore`.

## 7. UAT

Unit (deterministic): book read/write + section edits (append/update/delete); candidate enqueue is instant + durable. Integration (scripted curator model): two near-dup candidates -> 1 entry; trivial
candidate -> 0 added; better SQL for an existing pattern -> update (count stays 1); one rich turn -> N
entries across kinds; RCA turn -> an `rca_lead` keyed by the metric. e2e (retail): learn a pattern then a
same-shape query reuses it (fewer steps, no dup); RCA lead reused on a later RCA of the same metric;
trivial query learns nothing; turn latency ≈ baseline (curation off the hot path). Metrics in
`tests/uat_cases.csv`: bank size bounded, `% turns that learn` low, reuse hit-rate, latency delta ~0.
